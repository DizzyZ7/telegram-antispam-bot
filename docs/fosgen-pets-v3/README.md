# Fosgen Pets Graphics v3

Ветка от main `0c9b1d7`: `feat/fosgen-pets-graphics-v3`. Разработка шашек в
PR #129 остается отдельной. Новая графика предназначена для художественной
оценки через лабораторию, до переключения постоянной выдачи.

## Архитектура и постоянство

Чистый SVG v2 сохраняется без изменения: он подходит для прежнего контурного
стиля. Для объемного плюша выбран гибрид без production-модели и GPU:

1. `plush_assets.py` проверяет SHA256 закрытого каталога и 512px lossless WebP
   каждого вида. Кэширует до четырех сжатых файлов; декодированное изображение
   принадлежит только одному вызову. Все 12 основ вместе занимают 1,35 MiB.
2. `plush_materials.py` строит float32 поля окраса, органические маски, видовые
   особенности и редкие отметины. Локальный PCG64 получает SHA256 от seed и
   отдельного пространства имен. Глобального генератора случайностей нет.
3. `graphics_v3.py` сохраняет светотень и ворс мастера. Зрачки, блики и нос
   защищены; радужка получает ограниченный оттенок. Все слои проходят одну
   мягкую деформацию. Альфа ограничивает каждую маску. Затем добавляются фон
   и контактная тень.
4. `portrait.py` возвращает исходный PNG и самостоятельный SVG с этим же PNG
   внутри data URI. Cairo не перерисовывает v3. Тяжелая работа проходит вне
   asyncio loop, общий семафор ограничивает рендер двумя вызовами.

`asset_version=3`, `renderer_version=fosgen-plush-v3`. Состав полей DNA совпадает
с v2; список видов, палитр, рисунков, вариантов и вероятностей v3 заморожен
отдельно. Pillow/NumPy закреплены в requirements: изменение ассета, формулы,
геометрии или зависимости, которое меняет эталонные пиксели, требует новой
версии рендера/ассетов. Golden не обновляется автоматически для обхода сбоя.

Постоянный питомец хранит исходные DNA, PNG, SVG, SHA256 и pixel hash в
PostgreSQL. Чтение и повторный `/pet` возвращают сохраненные байты, даже при
другой новой версии выдачи. Перерисовки или миграции старых портретов нет;
истории, ID и ограничения владельца сохраняются. Один постоянный питомец на
пользователя глобально. Удаление/замена постоянного питомца не добавляются.
Сбой рендера или настройки Pets обрабатывается подсистемой и не останавливает
модерацию.

## Администраторская лаборатория

Нужны существующие `FOSGEN_PETTEST_ENABLED=1`, список
`FOSGEN_PETTEST_ADMIN_IDS` и личный чат с ботом. SQLite лаборатории изолирован
от PostgreSQL постоянных питомцев. Все выборки и удаления ограничены владельцем.

| Команда | Результат |
|---|---|
| `/pettest` или `/pettest kitten` | Новая случайная генерация в утвержденном стиле v3 |
| `/pettest v2` или `/pettest v2 kitten` | Явная генерация прежнего стиля v2 |
| `/pettest v3` | Случайный вид v3 |
| `/pettest v3 otter` | Новый тестовый зверек выбранного вида |
| `/pettest v3 series kitten 6 123456` | Одинаковые прочие гены, seed 123456–123461 |
| `/pettest v2 series fox 6 123456` | Явная серия v2 |
| `/pettest compare capybara 123456` | Пара v2/v3 с одинаковыми генами |
| `/pettest v3 rare bunny heart 123456` | Явная редкая отметина |
| `/pettest ID` или `/pettest ID dna` | Сохраненный PNG или полная DNA |
| `/pettest list` | Активные записи, занятые/свободные места |
| `/pettest ID delete` | Удаление своей тестовой записи |
| `/pettest 1,3,5-8 delete` | Атомарное удаление своих выбранных ID |
| `/pettest id 1-27 delete` | Совместимое удаление диапазона |
| `/pettest all delete` | Очистка всех своих временных записей |

Редкие имена: `star`, `heart`, `blaze`, `freckle`, `sock_left`, `sock_right`.
Серия: 2–8 записей. Pattern Seed 0–999999 с переходом через ноль. Лимит 30
активных записей; удаление сразу освобождает места, ID не переиспользуются.
Создание серии/пары атомарно: при ошибке или коллизии частичные записи не остаются.
Старые команды и уже сохраненные тестовые портреты остаются совместимыми.

## Воспроизводимые проверки

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -p 'test_*.py'
python -m fosgen_pets.gallery_v3 --output /tmp/fosgen-v3-gallery
python -m fosgen_pets.benchmark_v3 --rounds 2 --workers 2
```

Галерея содержит 204 настоящих PNG, полные DNA, миниатюры, portable `index.html`,
четыре PNG-листа и `metrics.json`. Полный режим покрывает все виды, все
совместимые рисунки с тремя палитрами, шесть серий по шесть seed, шесть редких
отметин на семи видах. `--quick` явно сокращает покрытие до 24 портретов.
CI заново собирает полный набор и сохраняет `fosgen-pets-v3-gallery` как
скачиваемый artifact на 14 дней, с PNG, HTML, DNA и метриками.

Метрики: file/visible RGB SHA256, DCT pHash, SSIM, изменение RGB, контраст и
гистограмма яркости. SSIM здесь — среднее по неперекрывающимся окнам яркости
8×8, population covariance, L=255; это документированный диагностический
вариант. Передний план у непрозрачного PNG оценивается по углам фона, поэтому
это приближение. Вне галереи тесты геометрии используют настоящую альфу.
Пороги зависят от вида/узора, высокое сходство solid допустимо. Ни SHA256, ни
ограниченная выборка не доказывают уникальность всех возможных DNA.

Golden: `tests/fixtures/fosgen_pets_v3.json` фиксирует DNA, исходные PNG и RGBA
для всех 12 видов. Старые fixtures не изменяются. Реальная геометрия проверяется
для всех совместимых рисунков: связность силуэта, поля, оба глаза, маски внутри
альфы. Есть тесты параллельного детерминизма, поврежденных ассетов, изоляции
администраторов, SQLite-миграций/лимита/отката, dispatcher, PG и ограничений RAM.

Для PG использовать только отдельную тестовую БД:

```bash
TEST_DATABASE_URL=postgresql://test:test@localhost:5432/entertainment \
  python -m unittest tests.test_fosgen_pets_postgres tests.test_fosgen_pets_v3_postgres -v
```

Каждый pet-тест создает собственную схему. Не направлять destructive integration
тесты на production. CI проверяет эти модули на PostgreSQL 17. Docker build
дополнительно рендерит все 12 видов v2 и v3 внутри реального образа.

## Включение и откат

Для публичного запуска недостаточно выбрать графику: нужно обновить бота,
включить учет и подключить группу. Пример для чата ИКФ, уже находящегося в
основном allowlist; используется существующий PostgreSQL DATABASE_URL:

```env
FOSGEN_PETS_ENABLED=1
FOSGEN_PETS_CHAT_IDS=-1002619489118
FOSGEN_PETS_NEW_ASSET_VERSION=3
FOSGEN_PETS_V3_ART_APPROVED=1
```

Участвовать может любой обычный пользователь подключенной группы. Сначала он
пишет `/pet_start` в личке с ботом, затем общается в группе. В личке
`/pet_progress` показывает прогресс, `/pet` после 100 подходящих сообщений
выдает постоянного питомца. До согласия сообщения не засчитываются. Команды,
пересылки, повторы и сообщения, не прошедшие модерацию, не считаются; действует
интервал 30 секунд между зачтенными сообщениями одного пользователя.
Один постоянный питомец закрепляется за пользователем, включая другие группы.

Лабораторный `/pettest` доступен только администраторам и не создает постоянных
питомцев или прогресс. После утверждения стиля его новая генерация по умолчанию
использует v3; это не включает публичную выдачу само по себе.

Значения по умолчанию остаются `FOSGEN_PETS_NEW_ASSET_VERSION=2` и
`FOSGEN_PETS_V3_ART_APPROVED=0`. Лаборатория может явно выбрать v3 отдельно.
После художественного утверждения владельцем и зеленого CI оператор может
одновременно выставить version=3 и art_approved=1. Этот PR этого не делает.
Неутвержденная или некорректная конфигурация отключает только Pets с безопасной
диагностикой. Слияние также остается за владельцем.

Откат новой выдачи — version=2, art_approved=0. Уже выданные питомцы v1/v2/v3
сохраняют прежние портреты; записи и исходные ассеты не удалять. Резервное
копирование действующего PostgreSQL и DATA_DIR следует существующему runbook.
