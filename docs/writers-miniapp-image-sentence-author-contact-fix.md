# Writers Mini App — фотографии, описание и связь с автором

## Что исправлено

### Фото и вложения
- Прежде Mini App только **выбирал** фотографии; на сервер они
  попадали только при финальной отправке. При закрытии окна файл
  исчезал из локальной очереди даже после успешного сохранения текста.
- Теперь кнопка **«Сохранить черновик и файлы»** сначала сохраняет текст,
  затем загружает выбранные файлы в существующее закрытое Telegram-хранилище,
  проверяет ответ сервера и записывает `cover_file_id` для платной обложки.
  Подписка на канал **@ff_info_ru** для сохранения черновика не нужна.
- Сервер допускает сохранение файла на приватном черновике, когда указаны
  название и тип работы, **даже если описание, рейтинг, предупреждения
  и т.д. еще не готовы**. Это не снимает ограничение на отправку:
  вся форма будет проверена на финальной кнопке.
- Сохраняются проверки владельца черновика, закрытого чата-хранилища,
  MIME и содержимого файла, максимум **3 файла / 20 МБ каждый**, защита
  от повторной загрузки и конфликтов версий.
- При проблемах HEIC / WebP в мобильном WebView по-прежнему требуется
  преобразование изображения в JPEG. Если конкретный WebView не умеет
  прочитать файл, пользователю выводится ошибка преобразования; небезопасные
  неизвестные форматы не проходят сервер.
- В браузерной форме обновлен cache-busting номер скрипта для Android/iOS.

### Предложения и хештеги
- У большой работы нужны **как минимум три законченных предложения**
  (со знаками `.`, `!` или `?`) и максимум 110 слов.
- Следующие за ними `#хештеги`, emoji и дополнительная незавершенная
  фраза больше не вызывают ложную ошибку.
- Клиентский счетчик и серверная валидация используют одинаковый принцип.
  Два законченных предложения и третий фрагмент без пунктуации не проходят.

### Контакт автора для администрации
- Каждая карточка модерации показывает **числовой Telegram ID** и
  кликабельную ссылку `tg://user?id=<id>` на того же пользователя.
- Бот пытается получить имя и `@username` через **собственный Telegram
  Bot API по проверенному ID автора**, а не из текста анкеты.
- Если `@username` отсутствует — выводится отображаемое имя.
  Если пользователь скрылся/заблокировал бота и lookup не сработал —
  ID и Telegram-ссылка остаются в карточке. Связь через ссылку зависит
  от клиентских ограничений и приватности Telegram.
- Дополнительные имя и ник не сохраняются в PostgreSQL и не публикуются
  в открытых каналах; сведения видит только модератор.

## Проверка перед развертыванием

1. С iPhone/Android открыть новую форму, ввести название и выбрать ФФ/Оридж.
2. Выбрать `JPG` или `PNG`, нажать **«Сохранить черновик и файлы»**.
   Дождаться `✓ Файл сохранен`, закрыть Mini App, открыть черновик:
   вложение должно остаться.
3. Дописать описание: `Первое. Второе. Третье. #романтика`.
   Ошибки о последнем знаке не должно быть.
4. Подписчик @ff_info_ru отправляет форму, модератор получает файл
   ответом на карточку и контакт автора. Неподписанный человек может
   сохранять черновик, но не отправлять на модерацию.
5. Аккаунт без публичного username должен показывать имя и контакт
   по ID без выдуманного `@username`.
6. Zero Trust входа в группу, публикационная проверка канала
   и существующая логика модерации не меняются.

Новых ENV и ручных миграций нет. **PostgreSQL и DATA_DIR не очищать.**
