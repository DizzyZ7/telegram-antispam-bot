# Замена нежелательного мема

Уточнение пользователя 12.11.2026: правило и команды настройки действуют во всех группах/супергруппах, включая Lexicon-only. Стикер хранится отдельно по chat_id. Личка и каналы исключены. Это уточнение заменяет ограничения Writers scope в исходном описании ниже; остальные функции и allowlist не расширяются.

Пользователь поручил реализовать удаление сообщений со словами «могнул», «могнули», «могнешь», установку одного ответного стикера через команду и возврат исправленного сообщения. Реализация продолжает существующий Python/aiogram, без внешнего ИИ.

Выбор исполнителя: отдельная политика для семейства «могнуть», без поиска подстрок в обычных словах. Замена «муркнуть» сохраняет окончание и регистр. Модерация работает только в текущем Writers/ИКФ scope, включая его темы; отдельный Lexicon-only чат и личка не расширяются. Ограничения исключенных от мата тем остаются исключениями только для мата.

Подход: отдельный middleware до Entertainment learning, с прежним приоритетом обычной модерации мата. Альтернативы отклонены: добавление в словарь мата ошибочно начисляло бы нарушения за мем; фильтр только на выходе оставлял бы сообщения в чате. Новая политика также закрывает вход, исторические источники и выход Entertainment, не меняя саму генерацию.

После подтвержденного удаления: очищается память сообщения, отправляется настроенный стикер и исправленный текст. Не копировать обратно мат, оскорбления и унижение. Никакой HTML/Markdown-интерпретации и превью ссылок; не отвечать на уже удаленный message_id. Сохранить тему. Для подписей сохранить повторно доступное медиа по file_id и исправить подпись; длинный текст разбивается по лимиту Telegram без потери символов. Не повторять неопределенную отправку. Повторные update подавляются ограниченным процессным кешем; при перезапуске повторная удаленная запись обычно отклоняется Telegram, распределенной транзакции Telegram/БД здесь нет.

Команды администратора только в ИКФ: `/set_mog_sticker` ответом на стикер, `/mog_sticker_status`. Непроверенные права не дают менять настройку. PostgreSQL через существующий небольшой конфигурационный pool, отдельный ключ Writers; локальный атомарный файл только в режиме без PostgreSQL. Ошибка записи не подтверждает сохранение и не заменяет рабочее значение. До установки стикера удаление/исправленный текст работают самостоятельно.

Реальные сообщения чата в ходе разработки не удаляются и не отправляются. Нет новых зависимостей, платных вызовов или изменений поиска Tavily.
