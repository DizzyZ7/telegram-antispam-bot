# Диагностика отказов поиска Фосгена

Проблема: после подключения ключа и учтенного запроса Tavily бот вернул «Пу пу пу» на вопрос о фотосинтезе. Доступные владельцу логи содержат строки запуска, но не категорию отказа. Конкретная причина боевого отказа пока неизвестна. По коду нормальные отказы пишутся через logger.info; запуск выводится через print. Нужна диагностика, доступная независимо от фильтрации INFO/stderr.

## Изменение

- Каждый завершенный поиск/отказ выводит одну безопасную структурированную строку FOSGEN_SEARCH_RESULT в stdout с flush. Только исход, известная категория, числовой HTTP-статус или none, длительность. Исходный вопрос, ответ, ключи, заголовки, тело HTTP и Telegram ID не выводятся.
- HTTP 401, 403, 400/422, 429, 432/433, 434, 5xx, редиректы, таймаут и другая ошибка связи различаются. У успешного HTTP 200 с отклоненным текстом сохраняется статус 200 и причина проверки.
- Пустой ответ, превышение 700 символов, ссылки/HTML, язык, безопасность и лексическая связь получают отдельные категории. Обработка и ограничения не ослабляются.
- Неизвестные сообщения исключений заменяются безопасной категорией. Значения HTTP принимаются только как целые числа от 100 до 599.
- Последний результат текущего chat_id+topic_id доступен через /fun_search_status только администрации разрешенного чата/темы. Команда не вызывает Tavily и не тратит кредиты. Проверка запрещенной темы выполняется раньше проверки администратора и чтения состояния.
- Хранится одна неизменяемая запись только с операционными значениями на область, максимум 256 областей LRU. Данные сбрасываются при перезапуске. Отсутствие thread_id и значение 0 обозначают одну область; ненулевые идентификаторы, включая 1, сохраняются по действующему normalize_topic_id в Entertainment.
- Обычный пользователь продолжает получать один короткий ответ или ровно «Пу пу пу». При неподтвержденном claim сохраняется молчание, а диагностика отмечает отказ хранилища. Повторы Telegram update не создают новый результат и не заменяют исходную причину. Доставку, завершившуюся неопределенно, видно в статусе; повторной отправки нет.
- Сохраняются базовый единственный запрос Tavily, бесплатный аккаунт, текущие таймауты, лимиты, запреты чатов/тем и все фильтры. Новых таблиц, зависимостей и переменных окружения нет.

## Проверка

Локальный HTTP-сервер воспроизводит HTTP-ошибки и некорректные ответы. Тест с выключенным logging доказывает видимость stdout. Проверяется состояние через экспортируемый сервис и настоящий зарегистрированный обработчик, права администратора, изоляция/ограничение кеша и отсутствие секретов. Полный Python/Node набор, одно независимое ревью, CI, затем main. После обновления контейнера владелец повторяет один вопрос и выполняет /fun_search_status в той же теме. Только полученный результат позволит установить причину боевого «Пу пу пу».
