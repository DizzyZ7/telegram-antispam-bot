# Проверка оформления заявки на Bothost (14 октября 2026)

## Причина старого оформления

Ветка main (SHA 433248ac) содержит старый render_owner_promo: заголовок 🎩, неприкрытые предупреждения, нет нижнего орнамента. Обновленный шаблон находится в PR #69; простое действие «Рестарт» старой сборки не меняет исходный код.

## В новом коде

- Заголовок: « <b>Название</b> » — пробелы перед/после текста, одна пара елочек, без дублирования кавычек.
- Список предупреждений, обрамленный символами ×, находится внутри HTML tg-spoiler; видимый заголовок остается за пределами спойлера.
- Низ поста: • • • • • • • • ✦ • • • • • • • •.
- Входящая заявка: служебная карточка с кнопками + отдельный форматированный пост как ответ на карточку + вложения/макет.
- После одобрения владелец тоже получает пост в новом формате. В канал автоматически ничего не публикуется.
- Для BotHost Python (без apt-пакета DejaVu) в requirements.txt закреплен font-roboto==0.0.1. При генерации макета бот проверяет настоящие кириллические глифы. Pillow ImageFont.load_default не используется — он создает квадраты вместо русских букв.

## Порядок безопасного выпуска

1. Проверить, что CI последнего коммита PR #69 зеленый. Перед объединением выполнить независимый код-ревью и тесты Telegram на iOS/Android.
2. Только после согласования объединить PR в main и убедиться, что Bothost получил именно новый commit SHA. При обновлении установятся новые requirements.
3. Перезапустить обновленную сборку в Bothost. В личной переписке с ботом написать /writers_format **от имени владельца**. Команда должна показать ikf-format-guillemets-spoiler-ornament-v3 и статус доступности кириллического шрифта.
4. Создать **новую** тестовую заявку со словом Название без кавычек и с предупреждением. Убедиться, что бот отправил отдельный пост ответом на карточку и весь список предупреждений скрыт Telegram-спойлером.
5. Проверить макет палитры с русским заголовком Легенда: буквы должны быть читаемыми, не прямоугольниками.
6. Ранее доставленные сообщения Telegram останутся прежними: код не редактирует историю.

## Если все еще старый формат

Проверить: обновилась ли ветка/ревизия, установлен ли font-roboto==0.0.1, не запущен ли второй экземпляр старого бота с тем же токеном. Если /writers_format не отвечает владельцу, скорее всего исполняется старый код или команда перехвачена другим обработчиком. Не очищать базу данных и DATA_DIR при обновлении.

Новых переменных окружения и обязательных миграций для шрифта/оформления нет.
