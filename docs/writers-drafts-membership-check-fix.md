# Writers Submission: сохранение черновиков при сбоях Telegram membership

## Причина

API возвращал `403 not_eligible` при **создании черновика**.
`WritersSubmissionService.create()` вызывал проверку членства
в чате авторов через Telegram `getChatMember`. Проверка могла вернуть
`False` не только для покинувших чат, но и при недоступном Telegram.
Форма показывала технический код вместо причины. Даже абсолютно
корректные 3 предложения и 110 слов на это не влияли.

## Исправление

1. **Создание черновика и автосохранение** требуют авторизованной
   Telegram Mini App с подписанной сессией, но не требуют онлайн-проверки
   членства. Изменения видит только автор. Создание ограничено 12
   новыми черновиками на интервал штатного rate limiter. Автосохранение
   уже созданного черновика не ограничено этим порогом.
2. **Отправка на модерацию** по-прежнему требует участия в чате.
   `member`, `administrator`, `creator` считаются участниками.
   Статус `restricted` также допустим **только если**
   Telegram `is_member=True`. Ушедшие или забаненные не
   могут подавать заявки.
3. **При сетевом/API сбое Telegram** отправка возвращает
   `503 eligibility_unavailable` и понятный текст о повторной
   попытке. Это не считается отсутствием членства.
4. **При реальном отсутствии членства** отправка возвращает
   `403 not_eligible` с объяснением о вступлении в чат авторов.
5. Счетчик описания больших работ в Mini App показывает и слова,
   и завершенные предложения, и отсутствие точки в конце.
   Ограничение (не менее трех завершенных предложений, не более
   110 слов) не меняется. Зарисовки — 35 слов / 230 символов.
6. Ни JSON-схема, ни существующие данные, ни переменные среды,
   ни настройки Bothost не меняются.

## Регрессии

- Не член чата может сохранять приватный черновик, но не отправлять.
- Сбой `getChatMember` не блокирует сохранение, а на отправке
  отдает `503` вместо ошибочного `403`.
- Участник с ограничениями (`restricted`, `is_member=True`)
  вправе отправлять заявку; `is_member=False` — нет.
- Проверка авторизации и принадлежности черновика не обходится.
- Ограничен поток создания черновиков для новых/временно недоступных
  участников.
- Python/PostgreSQL/Bothost Docker CI.

## Важно при обновлении

Перед перезапуском/повторным открытием Mini App скопировать **несохраненный**
текст из формы: веб-страница может потерять данные при перезагрузке.
После успешного CI развернуть актуальный `main` без удаления базы.
Если `503` сохраняется на отправке, проверить права бота
на `getChatMember` в чате авторов и доступность Telegram API.
