# Writers Submission — дружелюбная проверка сообщества ИКФ и реестр участников

## Сценарий автора

- Автор может **открыть Mini App, заполнить анкету, создать и сохранить
  черновик** даже до вступления в сообщество ИКФ.
- Приветствие в личных сообщениях Фосгена через
  `/start writers_submit` объясняет правило без давления.
- **Только при нажатии «Отправить на проверку»** сервер запрашивает
  свежий Telegram `getChatMember` в выбранном чате/канале.
- При отсутствии подписки автор получает **403** с добрым объяснением
  в Mini App; дополнительно Фосген старается отправить в ЛС
  личное приглашение с кнопкой «Вступить в сообщество ИКФ».
  Одному аккаунту — **не чаще одного приглашения в 24 часа**.
  Сам черновик и его текст остаются в PostgreSQL.
- Если Telegram временно недоступен, возвращается **503**, а автор не
  получает ложное сообщение, будто он покинул ИКФ.
- После вступления автор самостоятельно нажимает
  «Отправить на проверку» в сохраненной анкете.

Бот может написать первым только пользователю, который уже начал с ним
личный диалог. Если пользователь заблокировал бота, отправка ЛС
невозможна, но инструкция остается видна прямо в форме.

## Какое сообщество требуется

По умолчанию используется уже настроенный `WRITERS_CHAT_ID`, то есть
**существующий чат авторов**, чтобы не изменить внезапно
правила доступа действующего проекта.

Если членство требуется именно в **отдельном Telegram-канале ИКФ**:

```env
WRITERS_SUBMISSION_MEMBERSHIP_CHAT_ID=-100XXXXXXXXXX
WRITERS_SUBMISSION_JOIN_URL=https://t.me/official_ikf_channel
```

Оба параметра опциональны, но для строгой проверки другого канала
надо задать **правильный ID канала**. Бот должен быть его
**администратором**, чтобы reliably получать статусы пользователей
и события `chat_member`. Ссылка используется только для кнопки,
не дает права на отправку без подтвержденного членства.

Без `WRITERS_SUBMISSION_JOIN_URL` бот пытается получить
публичную ссылку `username` или `invite_link` через `getChat`.
Если ссылки нет, отправляет добрый текст **без выдуманной кнопки**.

## Что действительно можно собрать в БД

Bot API Telegram **не умеет возвращать весь список подписчиков канала**.
Он может проверить **конкретного пользователя** через `getChatMember`
и получать **новые события вступления / выхода** через `chat_member`
при соответствующих правах и подписке на тип обновления.

Создается таблица PostgreSQL `writers_community_members`:
`chat_id, user_id, status, is_member, source, observed_at, join_notice_at`.
Без ников, имен, телефонов, фотографий и текстов сообщений.

Источники записей:
1. Результат каждой фактической проверки `getChatMember`
   непосредственно перед отправкой заявки.
2. Обновления `chat_member` по нужному чату/каналу (только когда
   Telegram их доставляет).

Данные сохраняются после перезапуска. Старая запись **никогда не
заменяет свежую проверку** перед отправкой. Обратные и устаревшие
события не должны перезаписывать более новое состояние.

Таким образом это **реестр известных и проверенных аккаунтов**,
не доказательство полного состава канала. Для исторически полного
списка необходим иной источник данных, доступный администратору;
автоматической недокументированной «выгрузки всех» здесь нет.

## Внедрение и тесты

- Новых платных сервисов и LLM нет.
- Таблица создается автоматически при запуске формы;
  ранее сохраненные заявки и поля не изменяются.
- Включены unit/HTTP/regression/PostgreSQL тесты: различие членства
  и ограничения прав, личное приглашение, защита от флуда,
  события вступления/выхода, долговременные записи и изоляция чатов.
- Не очищать PostgreSQL на Bothost при выпуске.
- После обновления можно проверить командой `/start writers_submit`
  в личке Фосгена, затем отправкой черновика от пользователя,
  который пока не состоит в выбранном сообществе.
