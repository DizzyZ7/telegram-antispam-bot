# Восстановление несохраненного текста в Telegram Mini App

## Цель и границы

Во время набора Telegram WebView может быть принудительно закрыт ОС. Отправить еще один HTTP-запрос при закрытии нельзя гарантировать. Поэтому текст, не подтвержденный серверным PATCH/POST, временно копируется в \`localStorage\` и предлагается к восстановлению после нового входа.

Это дополнение к PostgreSQL-черновику, а **не** замена серверного автосохранения.

## Безопасность

- Ключ копии содержит Telegram user ID из \`initDataUnsafe.user.id\`; использовать хранилище можно только после подтверждения Telegram \`initData\` сервером.
- Содержимое резервной копии доступно на том же устройстве/в том же WebView. На общем устройстве это дополнительный риск приватности; кнопка «Удалить локальную копию» удаляет данные немедленно.
- Срок действия — **48 часов**. Истекшие данные удаляются при следующей попытке чтения. Объем ограничен 250 тысячами символов JSON.
- В резервную копию записываются только **поля текстовой анкеты и параметры выбора**. Не записываются бинарные файлы, Telegram initData, session cookie, токен бота и API credentials.
- При недоступном \`localStorage\` форма и автосохранение работают как прежде, но резервное восстановление не гарантируется.

## Алгоритм

1. На каждое редактирование создается/обновляется временный снимок полей. Для еще не созданного черновика сохраняется **тот же** \`Idempotency-Key\`, который будет передан POST: потеря ответа не должна породить дубликат.
2. После подтверждения создания черновика резервная копия связывается с полученными ID и версией, сохраняя возможный новый текст, набранный во время HTTP-запроса.
3. После подтвержденного сохранения именно этой версии и именно этих полей локальная копия очищается.
4. При следующем успешном входе пользователь видит предложение восстановить текст или удалить копию. Восстановление **не происходит автоматически**.
5. Если ID черновика уже известен, API GET перепроверяет принадлежность автору, редактируемый статус, редакцию и текущую версию. При точном совпадении восстанавливаются поля и запускается обычное автосохранение.
6. Если версия изменилась, но сервер уже содержит **то же содержимое**, дополнительная запись не нужна — копия очищается.
7. Если версия/редакция изменилась и поля отличаются, сервер **не перезаписывается**. Резервные поля выводятся в текстовое поле только для ручного копирования.
8. При проблемах сети или недоступности черновика резервный текст остается доступным для копирования.

## Проверки и ограничения

- Node тесты: сохранение/очистка, изоляция по пользователям, потерянный ответ POST, гонка POST + новый ввод, версии и редакции, stale conflict, TTL, квота localStorage.
- GitHub Actions: \`node --test tests/test_writers_emergency_recovery_client.cjs\` плюс обычные Python/Node/PostgreSQL и Docker проверки.
- Требуются проверки **реального Telegram**: Android и iOS, закрытие WebView во время набора и POST, перезапуск, повторная отправка, переход между устройствами, смена Telegram-аккаунта.
- Бинарные файлы по-прежнему нужно выбирать заново, если они не успели загрузиться на сервер.
- Нельзя гарантировать восстановление, если ОС очистила локальное хранилище WebView или пользователь сам удалил данные приложения.

## Выпуск

Функция не требует миграции PostgreSQL и новых переменных окружения. Ассеты Mini App версионированы \`draft-recovery-v7\` для инвалидации кеша. Не сливать PR до зеленого CI и smoke на настоящих устройствах.
