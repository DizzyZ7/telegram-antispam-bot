# Фосген / ИКФ — мобильные изображения, описание и связь с автором

## Проблема

- Ранее выбранная фотография в Telegram Mini App только оставалась
  **в оперативной памяти страницы** до кнопки «Отправить заявку».
  Закрытие Mini App удаляло выбор, а отправка файла требовала
  **полного заполнения анкеты уже перед загрузкой**, включая минимум
  три завершенных предложения. Пользователи воспринимали это как
  сломанную отправку изображений.
- Описание требовало не только трех законченных предложений,
  но и того, чтобы **весь текст заканчивался** на точку, знак вопроса
  или восклицания. Хештеги, emoji, незаконченная подпись в конце
  делали правильный текст якобы недостаточным.
- Администратор получал числовой user ID без быстрых ссылок на автора.

## Исправления

### Файлы

При выборе фотографии/вложения Mini App теперь:
1. Подготавливает JPG/PNG или преобразует поддерживаемые HEIC/WebP
   в настоящий JPEG (как раньше).
2. Сохраняет текущий текст **личного черновика** в PostgreSQL.
3. **Сразу загружает вложение** через существующий защищенный
   Telegram file staging и фиксирует его ID в черновике.
4. Отображает реальный прогресс отправки и подтверждение хранения.

Файл можно отправить **до заполнения всей формы**. Сервер проверяет
авторство черновика, лимит 3 файлов, допустимые MIME/сигнатуру и
максимум 20 МБ, а само произведение полностью проверяет только
при финальном отправлении на модерацию. Проверка подписки
на `@ff_info_ru` также остается на финальном шаге.

Для HEIC/WebP, которые конкретный Telegram WebView не умеет
декодировать, интерфейс объясняет необходимость выбрать JPG;
недоступное декодирование **не считается успешной загрузкой**.

### Описание

Для ФФ и ориджиналов действуют прежние требования:
**3 законченных предложения и максимум 110 слов**.
Они могут сопровождаться хвостом с хештегами, emoji или
незавершенной фразой — после трех корректных предложений это
не приводит к ложной ошибке. Сервер и браузер считают одинаково.
Мини-приложение отображает количество законченных предложений.

У зарисовок ограничение **35 слов / 230 символов**, без обязательных
трех предложений; оно не менялось.

### Telegram-контакт в карточке модератора

Фосген делает данные для обратной связи доступными **только
в приватной модерационной карточке**, никогда в публикации:
- `@username` и кликабельная ссылка на `https://t.me/username`,
  когда ник задан;
- **ссылка по user ID** `tg://user?id=...`, даже без username;
- имя Telegram, если ник отсутствует и оно было доступно при входе.

Telegram `initData` криптографически проверяются существующей
проверкой Mini App; сведения не берутся из обычных текстовых
полей, которые автор может подделать. При входе в Mini App
они сохраняются в минимальной таблице `writers_author_contacts`.
Перед отправкой модерационной карточки бот пробует получить более
свежий username через Telegram; если Telegram ответить не может,
используется ник, подтвержденный при входе, либо ссылка по ID.

Автор видит предупреждение о том, что модератор может использовать
имя, ник и ID для связи по заявке.

## Совместимость

Добавлена одна идемпотентная таблица PostgreSQL, без ручных миграций.
Новых переменных среды нет. Существующие черновики, приложения,
подписка на `@ff_info_ru`, Zero Trust вступления в группу,
модерация и публикации не меняют правил.

При обновлении Bothost сохранить PostgreSQL и `DATA_DIR`.
Файлы, которые пользователь выбирал **до обновления**, но не отправил
на сервер, могли оставаться только в памяти WebView — такие файлы
потребуется выбрать заново.

## Тесты

- Python: корректный счет предложений, HTML contact escaping,
  отсутствие username, username с Telegram live lookup.
- PostgreSQL: вложения доступны в неполном приватном черновике;
  подтвержденный профиль сохраняется и доступен только модерации.
- JS: три завершенных предложения с последующим хештегом/emoji;
  выбор файла вызывает сохранение черновика и немедленную загрузку.
- Полный Python/PostgreSQL/Bothost Docker CI.
