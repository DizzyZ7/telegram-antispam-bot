# Writers Submission — сохранение черновиков и проверка участия

## Что означала ошибка `not_eligible`

Сервер при **создании первого черновика** и при **отправке заявки**
проверяет Telegram-участие автора в `WRITERS_CHAT_ID` через
`bot.get_chat_member(chat_id, user_id)`. При старой реализации
любой сбой Telegram был ошибочно представлен как "не участник".
Также ошибочно отклонялся статус `restricted` с
`is_member=True` (пользователь все еще в сообществе).

Отображаемая ошибка не имеет отношения к длине описания.

## Исправления

- `member`, `administrator`, `creator` допускаются.
- `restricted` допускается **только если `is_member=True`**.
  `left`, `kicked` и `restricted` с `is_member=False`
  остаются не допущенными.
- Telegram API/доступность бота — отдельный ответ
  **HTTP 503 `eligibility_unavailable`** вместо
  HTTP 403 `not_eligible`.
- Проверка по-прежнему **fail closed**: заявки не отправляются,
  пока реальное членство не подтверждено.
- Приложение различает два случая и сообщает на русском,
  что нужно проверить членство либо права бота.
- При невозможности сохранить новый черновик появляется
  **«Скопировать текст анкеты для сохранения»**.
  Копирование запускается только по нажатию. В буфер помещается
  JSON со всеми текстовыми полями на момент копирования;
  приложенные файлы не копируются. В localStorage без согласия
  ничего не сохраняется.
- Прежние черновики уже можно открывать и редактировать
  без повторной проверки членства; финальная отправка
  требует актуальной проверки.

## Что проверить администраторам

1. Убедиться, что пользователь состоит именно в **писательском
   Telegram-чате**, а не только в связанном канале.
2. Убедиться, что `WRITERS_CHAT_ID` указывает именно на этот чат.
3. Убедиться, что Фосген находится в этом чате и имеет права
   администратора для надежного чтения статусов других участников.
4. Проверить логи `WRITERS_ELIGIBILITY_CHECK_UNAVAILABLE` (содержат
   ID чата и тип ошибки, но не данные анкеты).

Изменение не требует новых ENV/миграций. На Bothost после зеленых
Python/Postgres/Docker тестов пересобрать main, сохраняя PostgreSQL.

## Границы

**Не** разрешаем обход проверки в режиме ошибки Telegram, в том
числе для отправки: из соображений защиты заявок. При недоступности
Telegram автору нужно использовать кнопку копирования, пока
сервер не сможет подтвердить участие.
