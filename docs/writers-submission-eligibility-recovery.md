# Writers Submission — свободные черновики и проверка сообщества ИКФ

## Правила подачи

**Все авторизованные через Telegram Mini App пользователи** могут создать
черновик, заполнить и автосохранить анкету, загрузить допустимые вложения
и вернуться к ней позже — даже если пока не состоят в сообществе ИКФ.

**Только кнопка «Отправить на проверку»** проверяет актуальное членство через
`getChatMember`. При отсутствии членства:
- работа остается **DRAFT** в PostgreSQL, включая вложения;
- веб-форма показывает дружелюбную подсказку;
- Фосген пробует **один раз за 15 минут** написать в личку с приглашением
  вступить в ИКФ, сохранить и отправить работу позднее;
- при наличии корректной ссылки добавляется кнопка «Вступить в ИКФ»;
- если личка с ботом еще не открывалась, Telegram может не доставить
  сообщение — отказ в Mini App остается понятным.

Сервис не отправляет материалы модераторам до подтверждения подписки и
не обходит проверку при ошибке Telegram.

## Конфигурация

Сохраняется обязательный `WRITERS_CHAT_ID` для существующих функций ИКФ.

При необходимости проверять подписку **в канале**, а не в писательском чате,
можно указать:

```dotenv
WRITERS_SUBMISSION_MEMBERSHIP_CHAT_ID=-100<id_вашего_канала>
WRITERS_SUBMISSION_COMMUNITY_URL=https://t.me/<имя_канала_или_приглашение>
```

Это **не готовые реальные ID/ссылки**; администратор заменяет значения на
свои. Если первая переменная не установлена, проверяется `WRITERS_CHAT_ID`.
Если вторая переменная не установлена, Фосген пытается получить публичный
username или уже доступную пригласительную ссылку через `getChat`.
Новые ENV **не обязательны** при проверке писательского чата.

Бот должен быть **администратором канала/чата**, чтобы надежно проверять
статусы других пользователей и получать `chat_member`-обновления.

## Реестр наблюдаемого членства

В существующем PostgreSQL автоматически создается таблица
`writers_community_members` с минимальными полями:

- chat_id и user_id;
- статус Telegram и булево is_member;
- источник: `live_lookup` или `chat_member_update`;
- время проверки/события (для защиты от запоздалых обновлений).

Реестр получает пользователей **по мере их проверки и новых событий
вступления/выхода**. Он **не является полным списком подписчиков канала**:
официальный Bot API не предоставляет метода перечисления всех участников
канала задним числом. `getChatMemberCount` дает только численность;
`getChatMember` — статус одного известного человека. Для новых событий
`chat_member` требуется администраторский доступ бота и разрешенный
тип обновлений. База не содержит сообщений, ников или личных анкет.

**Даже если человек есть в базе, перед отправкой всегда выполняется свежая
проверка через Telegram.** Ни прошлый статус, ни заявка другого человека
не открывают доступ автоматически.

## Исправленная прежняя ошибка

Раньше любой сбой `getChatMember` отображался как `not_eligible`,
а участник со статусом `restricted(is_member=True)` ошибочно считался
неучастником. Теперь:
- `member/administrator/creator`, а также `restricted` при
  `is_member=True` допускаются к отправке;
- `left/kicked/restricted(is_member=False)` не допускаются;
- сбой Telegram/прав бота — **HTTP 503 `eligibility_unavailable`**,
  а подтвержденное отсутствие членства — **403 `not_eligible`**.

Старые v3 ограничения жанров, предупреждений, зарисовок и описаний
не изменяются. Если серверное автосохранение невозможно по другой причине,
кнопка «Скопировать текст анкеты» позволяет сохранить поля отдельно
(без вложений).

## Выпуск

Добавляются только идемпотентная таблица PostgreSQL и необязательные
переменные окружения; ручные миграции и очистка БД не требуются.
Обновить Bothost из main **после зеленого PR и main CI**.
Данные PostgreSQL сохранять.
