# Mini App: диагностика обращения в техподдержку

После обновления Mini App отправляет с согласия автора короткий технический
отчет в существующий чат поддержки. Старую открытую вкладку нужно закрыть и
заново открыть через бота, чтобы загрузился новый JavaScript.

В отчете есть проверенный Telegram ID и @username при наличии, версия Telegram
WebApp API, платформа, ОС и браузер/WebView, сборка формы и состояние сети.
Для черновика передаются только UUID, версия, статус, флаги сохранения и
количество вложений. Клиентские диагностические данные не считаются доказанным
состоянием PostgreSQL.

Последний сбой содержит этап (`create`, `save`, `submit`, `upload`, `session`
и другие), метод, HTTP-код, стабильный код ошибки, поле и правило валидации,
время UTC, длительность и `ref`. `HTTP 0` означает отсутствие HTTP-ответа или
локальную проверку (`LOCAL`). Например, `description_sentences` объясняет
отказ проверки числа предложений без передачи самого описания.

Сохраняются восемь последних технических событий только в памяти вкладки.
Проверочные GET после неудачной записи не затирают ее причину. Если сервер
вернул некорректное подтверждение с HTTP 200, это отражается как
`invalid_response` с исходным номером запроса.

Каждый API-ответ содержит `X-Request-ID`. Этот же номер записывается в
`WRITERS_HTTP_REQUEST reference=...`, а для необработанного исключения — еще и
в `WRITERS_FORM_UNHANDLED_ERROR reference=...`. Номер самого обращения также
возвращается автору. Для проверки работ по ID используй существующую команду
`/writers_audit <Telegram ID>` в разрешенном администраторском контексте.

Содержимое формы, ссылки автора, имена и содержимое файлов, cookies,
токены, raw User-Agent, stack trace и произвольные тексты ошибок в отчет
не отправляются. Подпись Telegram или действительная подписанная cookie
обязательны; ограничение — три обращения за окно rate limit. Отправка
поддержки не требует доступа к PostgreSQL.

Первое старое обращение с `save_failed` нельзя дополнить задним числом:
старый клиент не передал причину. По ID можно проверить работы через audit;
для нового подробного отчета автору нужно повторить проблему после обновления
формы и нажать «Техподдержка».
