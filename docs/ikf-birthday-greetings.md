# Поздравления Фосгена с днем рождения

Общий лимит — одно поздравление с днем рождения на весь чат за календарный
день по Москве. Все темы, адресные планы и обычные реакции делят одну запись
в БД; перезапуск и другие реплики бота лимит не сбрасывают.
Единственное утвержденное исключение — персональное поздравление @pupsan99
24 ноября 2026 года, которое можно дослать один раз, если предыдущая
сборка уже успела отправить обычное поздравление в этот день.
Это исключение не меняет лимит для других дат и получателей.

Первое человеческое «с днем рождения» запускает одно теплое поздравление
Фосгена. Повторные поздравления любого участника в любых темах этого же чата
не создают дополнительных сообщений. Учитываются только свежие сообщения текущего московского
дня, включая подписи к фото; боты, пересылки и поздравления с другими событиями
не запускают деньрожденную реакцию. Поддерживаются «с днем рождения», «с др»,
«сдр», «с днюхой», «с днем варенья» и Happy birthday.
Обычные реакции учитывают выключенный `/fun`, запрет автономного текста и тихие
часы. Адресный план, который администратор явно согласовал, остается исключением.

Тексты состоят из цельных авторских вступлений, пожеланий и завершений:
2304 комбинации без разрыва слов эмодзи или копирования сообщений из памяти.
На разных днях вступления сменяются, а выбор сохраняется при перезапуске.

Одноразовые планы хранятся в `entertainment/birthday_plans.json`, внутри
пакета приложения, а не в каталоге runtime-данных `/app/data`. Для запуска
нужно развернуть эту версию бота и оставить процесс работающим. Изменять
переменные окружения или вручную запускать миграцию не требуется.

Одноразовые адресные планы:
- @Buketsireni, чат ИКФ `-1002619489118`, 3 ноября 2026 года в 12:30 МСК.
  Поздравление сказочнице с теплым текстом, согласованным владельцем.
- @pupsan99, чат ИКФ `-1002619489118`, 24 ноября 2026 года в 13:20 МСК.
  Личное поздравление владелице ИКФ и писательнице от Фосгена, который
  появился благодаря ей, с шуткой
  про праздничного енота. Для этого плана `allow_early=false`: никакое
  раннее поздравление участника не отправит текст до 13:20.
  `catch_up_after_generic=true` позволяет отправить его при первом
  тике supervisor после пересборки, даже когда предыдущее обычное поздравление
  от версии без этого плана уже заняло дневной слот.

Личные имена, возраст и названия непубличных произведений не используются.
Каждый план действует только в указанную дату и не повторяется ежегодно.

Для планов с `allow_early=true` (поведение по умолчанию) бот может присоединиться
раньше назначенного времени к поздравлению от человека, если тот упомянул
точный @username или ответил на сообщение именинника. Для планов
с `allow_early=false` отправка происходит только по расписанию в указанный
день, даже если участники поздравляют адресата заранее.
Общее «с днем рождения», поздравление другому участнику, неоднозначный список
получателей, бот или пересланное сообщение раннюю отправку не вызывают.
Ответ имениннице с явным поздравлением другому человеку также не подходит.
На дату адресного плана общий слот зарезервирован для него: обычный движ
с поздравлениями не создаст второго сообщения и не вытеснит согласованный текст.
Запрещенные развлекательные темы сохраняют свое ограничение.

Если ранней отправки не было, минутный supervisor отправляет поздравление
первым тиком после назначенного времени. Обычная случайная активность, лень и отсутствие
свежих сообщений для этого не требуются. Используется только настроенный
allowlist чатов. План не повторяется ежегодно. При позднем запуске в тот же
день бот догоняет расписание; со следующего календарного дня план истекает.

Таблица `entertainment_birthday_delivery` создается автоматически в PostgreSQL
и SQLite. До обращения к Telegram сохраняется уникальная заявка на отправку
по `(chat_id, local_date)`.
Для однократного досыла @pupsan99 автоматически создается отдельная таблица
`entertainment_birthday_recovery_delivery` с уникальностью по
`(chat_id, event_id)`. Новый релиз не очищает запись обычного поздравления.
Исключение жестко ограничено парой ИКФ/`ikf-2026-11-24-pupsan99-birthday`
и московской датой 24.11.2026. Подтверждение обычного поздравления в Telegram
есть в чате (сообщение 586679), поэтому досыл не зависит от того, как
старая сборка сохранила запись: `SENT` без ID, `CLAIMED`,
`UNCERTAIN`, другой старый event ID или отсутствие дневной записи.
Если дневной слот уже принадлежит персональному плану, повтор запрещен;
неопределенные отправки других событий также блокируют досыл.
Отдельный уникальный receipt сохраняет `SENT` или `UNCERTAIN`,
исключая повторы при нескольких воркерах и рестартах.
После 24 ноября по МСК этот план не отправляется. Адресная реакция, общий движ и таймер делят
одну запись. После успеха сохраняются `SENT` и Telegram message ID.
После ожидания БД дата проверяется заново: просроченное поздравление не уходит.
При переходе через полночь дата успешной доставки берется из ответа Telegram.

Подтвержденный отказ Bot API освобождает запись для следующей попытки.
При сетевом timeout, серверной ошибке Telegram или потерянном ответе статус
становится `UNCERTAIN`; бот не отправляет поздравление повторно вслепую.
Если процесс остановился во время отправки, может остаться `CLAIMED`.
Эти два статуса требуют сверки с чатом и блокируют новые поздравления этого
чата, включая следующие сутки, пока прежний исход не подтвержден: API Telegram не дает гарантии
exactly-once при потере ответа. Удалять запись для повтора можно только
после ручной проверки, что поздравление действительно не появилось.
Если оно появилось, нужно подтвердить `SENT`, Telegram message ID и его реальную
московскую дату вместо удаления строки. История подтвержденных доставок не
должна очищаться для восстановления неопределенной попытки.

Диагностика после запуска сборки: `BIRTHDAY_PLAN_LOADED`,
`BIRTHDAY_PLAN_DUE`, `BIRTHDAY_RECOVERY_CLAIMED` (одноразовая запись)
или `BIRTHDAY_RECOVERY_NOT_CLAIMED` (сведения о дневном слоте или отдельной
записи не позволяют отправить). Отсутствие `BIRTHDAY_PLAN_DUE` после
13:20 МСК означает, что нужно проверить версию, часы, чат allowlist
и запуск supervisor. Для уточнения состояния пригодятся только SELECT
из `entertainment_birthday_delivery` и
`entertainment_birthday_recovery_delivery`; не удаляйте записи ради повтора.

Диагностика: `BIRTHDAY_DELIVERY_SENT`, `BIRTHDAY_DELIVERY_REJECTED`,
`BIRTHDAY_DELIVERY_UNCERTAIN`, `BIRTHDAY_DELIVERY_STORAGE_FAILED` и
`BIRTHDAY_PLANS_LOAD_FAILED`. Репозиторий и тесты подтверждают готовность кода;
факт доставки подтверждается Telegram message ID и сообщением в чате.


## Отдельная однократная отправка Пупсан — 24 ноября 2026 года

После неоднократного молчаливого пропуска по старому supervisor персональное
поздравление `@pupsan99` переведено на независимый startup-путь
`pupsan_oneshot.py`. Он вызывается в `main.py` **после открытия
Entertainment Storage и до запуска supervisor и Telegram polling**.
При этом прежний адресный план Пупсан исключен из production supervisor,
чтобы он не конкурировал с отдельной отправкой.

В 13:20–23:59 МСК 24 ноября 2026 года модуль однократно делает прямой
`bot.send_message` **в тот же чат ИКФ**, ответом на уже опубликованное
сообщение Фосгена `586679`, чтобы попасть в исходную тему обсуждения.
Если Telegram явно отклонил ответ на сообщение, модуль один раз пробует
отправить текст непосредственно в чат. Строка с `SENT` содержит
фактический Telegram message ID и прямую ссылку.

Независимый журнал `fosgen_one_shot_delivery` в PostgreSQL хранит
`event_id=ikf-2026-11-24-pupsan99-one-shot-direct`,
`status`, `updated_at` и `telegram_message_id`. Уникальный `event_id`
обеспечивает одну выдачу при нескольких инстансах, рестартах и пересборках.
Подтвержденный отказ Telegram сохраняется как `REJECTED` и разрешает
повторить попытку после исправления прав/конфигурации; успешный `SENT`
никогда не повторяется. При неизвестном результате Telegram/сети
ставится `UNCERTAIN` и повтор вслепую запрещен. Оставшийся после
падения процесса `CLAIMED` также не повторяется автоматически:
без подтверждения Telegram невозможно строго гарантировать одновременно
at-most-once и eventual delivery.

Эта отправка намеренно не опирается на старые таблицы и лимиты
`entertainment_birthday_delivery` и `entertainment_birthday_recovery_delivery`,
которые до этого блокировали персональное поздравление. В остальных
датах ничего не отправляется.

Логи Bothost (stdout):

- `PUPSAN_ONESHOT_HOOK_REACHED` — startup-хук достигнут, указано московское время
- `PUPSAN_ONESHOT_CLAIMED` — уникальная попытка зарезервирована в PostgreSQL
- `PUPSAN_ONESHOT_SENT` — Telegram подтвердил отправку, напечатаны ID и ссылка
- `PUPSAN_ONESHOT_ALREADY_CLAIMED` — новая попытка не требуется; выведен статус
- `PUPSAN_ONESHOT_REJECTED` — Telegram отклонил, есть тип ошибки
- `PUPSAN_ONESHOT_UNCERTAIN` — возможно, Telegram принял сообщение, нужен осмотр чата
- `PUPSAN_ONESHOT_ERROR` — ошибка БД/токена

Если основной startup-хук не запускался, в окружении контейнера можно
использовать точно тот же механизм и тот же журнал, без дублей:

```bash
python -m pupsan_oneshot
```

Это одноразовый модуль только для сегодняшней даты, не повторяющийся ежегодно.
